# 数据分析智能体：Docling + 证据链演示版

本项目按照老师交付要求中的“Part 3 数据分析 Agent”和《数据分析Agent技术方案》实现。数据分析智能体可独立完成陌生数据包的导入、统一解析、OCR、去重、相似聚类、自适应建树、节点摘要、概览 Word 和待整编数据包导出。

> 演示例外：正式要求是物理断网和本地大模型。本版本仅把摘要增强临时接到 DeepSeek 云端；解析、OCR、文件哈希、去重、聚类、分类建树、证据链和本地概览底稿均在本机执行。未勾选云端确认时不会发送正文。

## 已实现的交付能力

- 三项交付：交互式目录/分析树、自动生成的《数据包情况概览报告》Word、可通过物理介质转交的“待整编数据包”ZIP；
- Docling 2.119 统一文档模型，支持 PDF、DOCX、PPTX、XLSX、图片、HTML、Markdown、CSV 等；
- RapidOCR 3.9.2 + ONNX Runtime，固定使用项目内 PP-OCRv5 mobile 检测/识别模型；
- DOCX、PPTX、XLSX 中的内嵌图片会再次送入 RapidOCR，OCR 文本回填统一正文，并按段落、幻灯片或媒体对象生成证据；
- 每个文件夹都有本地简易摘要，节点摘要引用代表文档及 evidence_id；小于 64 KB 的文件不额外生成简易摘要，但仍可查看统一文档、证据链并生成云端深度摘要；
- 提供“快速解析”和“高精度解析”两种模式：快速模式优先使用轻量正文提取，扫描型 PDF 仅 OCR 前 3 页预览；高精度模式保留 Docling 版面分析、TableFormer 和完整 OCR；
- 单篇文献按统一正文连续分块，逐块云端分析后全文合并，避免只读开头；
- SHA-256 包内精确去重；64-bit SimHash + 8-band LSH + 特征包含率高相似文档聚类；
- 根据统一解析后的正文语义自动判定内容类别，并以跨文档高频主题继续细分，生成不依赖文件类型的自适应分析树；
- 证据链记录文件路径、页码/章节、原文片段、版面框、解析器、OCR 置信分、源文件和片段 SHA-256；
- 本地混合检索 RAG 使用 BM25 + TF-IDF 字符向量对证据块排序，支持按整个数据包或当前节点检索，不调用云端模型；
- 解析结果保存正文覆盖率、截断状态、Office 图片 OCR 字符数和证据块数量，禁止把抽样或截断结果表述为完整覆盖；
- 完整分析后自动生成概览 Word，同时保留“重新生成”入口；
- 推荐研究方向明确标注为“推论”，包含研究问题、方法、置信度和证据依据；
- 文件夹云端深度摘要采用均匀抽样、分组并行和最终合并，并显式显示真实总文件数与抽样覆盖；
- 任一步骤失败均保留可见告警，并自动降级到兼容解析、本地摘要或本地 Word，不返回空文件。
- 同一扫描任务重复点击会复用活动任务；前端在分析完成前锁定重复提交，后端只保留最新的排队任务并显示当前占用资源任务的进度；本地解析并发和云端请求并发均有上限，服务重启会把未完成任务标记为可重试中断。

## 输出边界

数据分析智能体生成的概览报告用于快速摸清数据包，不等同于报告整编智能体生成的正式专题报告。证据链作为节点摘要、研究方向和导出包的可追溯附件；不会把本模块扩张为报告整编模块。

导出的 ZIP 包含：

1. 选中节点的原始文件；
2. `节点摘要.json`；
3. `证据链.json`；
4. `统一文档索引.json`；
5. `去重与聚类清单.json`；
6. `导出清单.json`。
7. `检索证据.json`；
8. `解析覆盖率清单.json`。

## 推荐演示流程

1. 输入本地数据包目录，点击“导入并分析”；
2. 一般演示选择“快速解析”；需要完整PDF版面、表格和图片证据时选择“高精度解析”；
3. 观察解析、去重、聚类、建树与 Word 自动生成进度；
4. 在“原始目录”和“自适应分析树”之间切换；
5. 选择文件夹查看本地节点简易摘要、代表文档和证据链；
6. 选择文件查看正文预览、覆盖率和证据；
7. 对非敏感演示材料勾选云端确认，再生成全文深度摘要；
8. 在“本地证据检索（RAG）”中输入问题，检查相关度、证据位置与哈希；
9. 下载自动概览 Word，或手动重新生成云端增强版；
10. 选择节点导出待整编数据包 ZIP。

## 主要目录

- `app.py`：Flask API、后台分析任务、自动概览流程；
- `services/unified_parser.py`：Docling 统一解析、PP-OCRv5 OCR、兼容降级与证据单元；
- `services/package_analysis.py`：去重、相似聚类、主题聚类、自适应树和节点摘要；
- `services/retrieval.py`：BM25 + TF-IDF 本地混合检索和证据排名；
- `services/document_analysis.py`：单篇全文分块阅读与合并；
- `services/folder_analysis.py`：大文件夹云端深度摘要；
- `services/reporting.py`：概览内容与研究方向；
- `services/exporter.py`：Word 与待整编 ZIP；
- `data/agent.db`：扫描、统一文档、证据、摘要、分析任务缓存；
- `models/rapidocr`：PP-OCRv5 mobile ONNX 模型；
- `models/docling`：Docling 版面/表格模型；
- `outputs`：Word 和 ZIP 输出；
- `docs`：技术方案与需求对照说明。

## 生产化边界

- 演示版使用 Flask 后台线程；生产环境应替换为持久化任务队列，并加入暂停、恢复、资源限流和任务审计；
- 当前已经实现单机任务幂等、并发限制和重启中断恢复，但尚不等同于跨进程持久化调度系统；
- SimHash LSH 适合本地演示和大批量候选召回，正式版本应按业务样本标定阈值并加入人工确认；
- 概览 Word 已保证失败时有本地完整底稿；正式离线部署时把 DeepSeek 客户端替换成本地量化模型即可保持上层接口不变；
- 处理几百 GB 数据包时建议统一文档正文和证据正文改为分文件对象存储，SQLite 仅保存索引与任务状态。
