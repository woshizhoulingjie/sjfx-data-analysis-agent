# 文件保护 2.1：范围、验证和启用

## 本次修改边界

仅修改 `sjfx_protection/`。不修改主应用、导入、大小数据包、情报概览、任务 worker、共享配置、主页面和生产环境开关。Windows 助手安装包不替换；沿用已存在的签名和处置协议。

## 能力与使用

1. 在 `/protection` 登记服务器资料目录，再通过本机助手选择本地对应目录。系统不能仅凭服务器路径推算任意电脑上的路径；通过账号、设备签名、SHA-256 和本地文件身份建立对应关系。内容一致不证明复制因果。
2. 新增“**双端路径与版本**”查看服务器路径、本地路径、设备在线状态、内容一致性及监控状态。`GET /protection/api/trace?file_id=...` 仅返回当前账号的数据。旧运行进程没有版本能力标识时，页面不显示此按钮。
3. 本地修改缺少当前指纹、监控记录缺口、路径冲突时，旧关联不再满足强制模式的访问条件。乱序事件保留在履历中，但不回滚较新的文件状态。监控缺口使待执行处置失效，需要重新关联。
4. 已确认危险内容的本地绑定和同内容副本都会排队隔离；文件版本变化使旧命令失效。排队不等于阻断成功，只有助手 `completed` 回执才标记处置完成。文件已被隔离后重新出现，也会再次排队。确认危险的版本不能直接从页面恢复。
5. 检查邮件 HTML 和附件、伪装可执行文件、危险扩展名、宏、压缩包目录跳转、解压膨胀和嵌套限制。纯被动检查，不打开外链、不执行附件、不解压落盘。静态策略阻止附件凭据收集表单，但不是对所有钓鱼邮件的识别保证。引擎缺失/失败不会显示为安全。
6. 服务器目录核验记录文件新增、修改、替换、改名/移动及删除；变化后旧清单失效，需要重新登记。保留旧版本的风险证据，不将新版本错误视为已获批准。
7. 系统请求与拦截均记审计事件；仅无文件目标的状态/进度轮询允许合并，文件读取不再被粗粒度去重。

## 生效与兼容

- Python 服务需要在与其他开发协商的重启窗口重新加载模块。`/protection/api/status` 返回 `protection_version: 2.1` 才表明新 Web 模块已加载。只修改源码不会替换正在运行进程中的 Python 类。
- 本次不自动重启主服务、不修改全局保护模式或主服务配置。原有 `audit` 模式只审计，不拒绝原业务；原有 `enforce`/账号策略继续控制强制校验。
- 数据库仅新增 `binding_clocks` 表和动作检索索引，旧业务表和原数据保留。旧版保护代码可忽略这些新增结构。
- 审计模式在使用已登记目录时异步核验版本，复用最多两个后台任务，不在请求中读取 NAS 文件内容。
- 可选独立观察器：在项目根目录用 `.venv/bin/python -m sjfx_protection.watch --state <实际文件保护状态目录> --interval 60` 启动；先加 `--once` 做单次验证。本次不自动安装、启用系统服务。使用现有保护数据库；不导入主应用或启动分析模型。资料过大时核验消耗 I/O，应先评估再启用。
- 观察器是快照比较：不能记录两次扫描间发生又恢复的变化，不记录服务器操作系统层面的每次文件读取，也不采集操作者进程。清单失效后不会自动重建或批准，需要用户重新登记。

## 不应声称已经实现的能力

“系统内所有操作”和“本地所有操作事前阻断”需要系统级审计/文件过滤器及可验证的端点部署，不能仅由 Web 服务或路径推算实现。本次不安装内核驱动、auditd 或新的端点服务，不保证任意软件外发、截图、已打开文件句柄、监控目录外的复制得到阻断。当前助手的覆盖范围、管理员权限、离线状态和回执必须如实显示；没有证据时不能显示为全量监控或已成功拦截。

## 验证与回滚

独立回归：`.venv/bin/python -m pytest sjfx_protection/tests -q`。测试使用临时目录、临时数据库和合成文件，不读取业务资料或触发实际隔离。原保护发布包测试同时保留在模块测试目录。

同步前校验每个旧模块文件的原始哈希；若检测到并发修改则停止，不覆盖。备份只包含本次覆盖文件，回滚时应先比较当前版本，不能覆盖后续他人的修改。回滚代码后也须在协商窗口重新加载服务；不要覆盖或恢复整个业务数据库。
