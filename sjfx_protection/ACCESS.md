# 文件保护：用户授权与管理员监视分离

## 页面与接口

- `/protection` 由后端根据真实登录角色选择页面；普通用户收到授权向导，管理员收到详细面板。
- `/protection/setup` 为本人授权向导，管理员也可以查看。
- `/protection/admin` 仅 `role == admin` 可访问。普通用户直接访问返回 403。
- 用户自助白名单仅包含状态、会话签名所需信息、配对、必要关联任务和本人设备撤销。未知接口默认拒绝普通用户。
- 文件、设备总览、绑定、监视事件、风险、预览、溯源、处置、策略、审计校验及服务器清单管理均由后端检查管理员权限。只读接口不接受 POST。
- 普通用户页面不请求监视数据，不输出服务器目录、文件本地路径、原始助手健康信息、风险规则、队列或处置回执。

## 用户知情与自助

用户仍须了解所选目录内会采集的文件信息、操作记录及可能执行的安全处置，不能将管理员可见等同于不告知用户。普通用户生成配对码前必须明确同意；同意事件记录告知版本。设备配对只归属于当前真实用户，不能通过请求参数指定他人账号。

自助撤销只允许当前用户自己的设备（同时验证 owner 和 user_id），并使其尚未使用的配对码过期。撤销服务器授权不等于远程终止本机进程，也不恢复已执行的文件隔离或权限限制；用户需要退出或卸载本机助手。如卸载提示仍有处置，须由管理员先完成恢复或其他安全处理。已有审计记录保留。

本轮未更改预编译 Windows 助手安装包。本机助手自身的页面和本机权限仍是独立边界；不能声称普通用户无法查看自己电脑上已有的本机信息。

## 管理员范围

用户系统已验证并保存在会话内的 viewing_owner 用于管理员管理视角。没有选择时默认为管理员自己的 owner，不默认跨用户聚合。不能用查询参数、请求体或请求头伪造角色或管理范围。管理员仍通过原有账号管理的视角切换功能选择其他用户。

配对和本人设备操作永远绑定真实登录账号；强制接入策略只在切回本人视角后可修改。status.mode 保持表示实际登录账号的模式，避免影响现有业务签名桥接。带设备签名的 `/agent/v2/*` 协议保持独立，不套用浏览器角色检查。

## 上线注意事项

只替换模板无法修复旧进程中的后端权限。必须由实际 Web 进程重新加载 integration.py 后才完成线上权限隔离。

普通用户模板在旧后端上检测不到 access_version=1 时停止新配对流程并提示升级，不假装已完成授权。不能把这个前端提示当成旧后端已被保护的证据。

本次代码修改和测试仅位于 sjfx_protection 内。不修改主应用、普通导入、大数据包导入、情报概览、共享配置，也不自动调整强制保护策略。若并行开发中不宜重载主进程，应约定重载窗口后再宣布上线完成。

验证：在独立临时目录执行 `.venv/bin/python -m pytest sjfx_protection/tests -q`，测试使用临时数据库和合成数据，不读取真实监视内容、不向真实终端下发操作。
