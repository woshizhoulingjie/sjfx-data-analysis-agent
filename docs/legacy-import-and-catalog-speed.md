# 旧格式导入与大数据包目录加速

本次仅修改格式解析适配层和隔离大包目录流程。源文件、普通摘要生成、问答、报告、人工目录名称和权限判断沿用原有逻辑。

## 文件导入

- DOC：antiword；PPT：按当前修订指针读取 OLE 幻灯片文本；XLS：xlrd；RTF：striprtf。RTF 内容的 DOC 文件按真实文件头路由。
- 普通导入、压缩包成员、深度解析共用 `UnifiedDocumentParser → scanner.extract_text → legacy_office`，返回原统一文档结构，再走原摘要流程。
- 保留原文件路径、原文件哈希和可追溯证据。不会把源文件转换或覆盖成其他格式。
- 原生读取进程有墙钟时间、地址空间、CPU 和输出文件上限；父进程取消时清理子进程。纯文本提取不执行 Office 宏。
- 大包画像调用同一个适配层的预览模式。常规文本等格式的原 64 KiB 预算保持原样；旧 OLE 容器需要完整偏移表，使用独立的容器读取上限。首轮默认 8 MiB / 文件、4 秒；补充识别 24 MiB / 文件、15 秒。超过预算的文件仍在清单，可选择深度解析，不伪造“完整读取”。
- 普通/深度旧格式读取默认单文件上限 512 MiB、60 秒、768 MiB 地址空间；所有原有单内容对象上限继续生效。RTF 预览可读前缀。
- XLS 保留工作表和行位置、日期、布尔值、错误值及公式缓存值，读取所有工作表或明确标记预算截断。不执行公式重算。
- PPT 读取当前文档的幻灯片列表和所引用正文，支持 Unicode 与形状文本，排除旧修订、母版及主题元数据。
- DOC/PPT/RTF 的内嵌图片、对象、批注不承诺完整覆盖；加密、损坏、空正文文件明确失败，不产生“已完整解析”的误导状态。

安装：`bash scripts/install_legacy_readers.sh`。原生组件安装在项目 `.tools/legacy-office`，Python 组件安装在项目虚拟环境，不修改全局系统包。迁移部署需一并安装该目录或系统原生组件。

## 目录生成

1. 盘点和内容画像仍按现有流程执行；语义向量、相似度阈值、项目边界和代表材料选择保持原样。
2. 内容分组与抽取式名称就绪后即可进入 70% 的范围选择界面；生成模型完善名称作为后台工作，不再阻塞选择。
3. 默认每次最多命名 4 个主题，共享提示词开销，保留每组原有代表内容和独立证据编号。每组仍执行原名称、证据、版本、人工锁和权限检查；失败组按单组流程重试。
4. 沿用现有请求数、时间和 token 预算账本，以及前台优先模型调度。只增加一个后台执行线程，不改变生成模型并发参数。
5. 分组成员数在同一 SQLite 事务内由触发器维护，迁移时一次性回填；避免每加入一个文件、每次命名排序和目录读取时重复扫描组内所有成员。已有分组和文件不重新分配。
6. 暂停、取消或进入深度解析时后台工作及时让出；过期内容版本结果不会覆盖新内容或人工命名。

调节参数：

| 参数 | 默认值 | 作用 |
|---|---:|---|
| SJFX_LP_CATALOG_BATCH_SIZE | 4 | 设为 1 恢复逐组命名 |
| SJFX_LP_CATALOG_BATCH_INPUT_TOKENS | 6500 | 一次请求总输入预算，超出则拆批，不删减组内证据 |
| SJFX_LP_LEGACY_PREVIEW_BYTES | 8388608 | 首轮旧格式容器读取上限，补充识别为三倍 |
| SJFX_LEGACY_MAX_BYTES | 536870912 | 普通/深度旧格式文件读取上限 |
| SJFX_LEGACY_MEMORY_MIB | 768 | 旧格式辅助进程内存上限 |

对百 GB 数据包，成本仍取决于文件数、单文件大小、格式、NAS 吞吐和模型负载。此改修减少目录命名请求及成员计数开销，并使首版目录无需等待模型命名；不能把小样本测试外推为任意百 GB 数据包的固定完成时间。
