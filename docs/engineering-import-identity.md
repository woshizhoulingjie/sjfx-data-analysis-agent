# 大包目录转普通导入：身份、版本与有效选择一致性

## 目标与范围

本轮沿用已有导入通道和普通 Worker，不重写目录算法，不复制大文件，不变更数据库表结构。
基线提交为 `af534ad1a1493e741f3c09acb04f7a07624d0527`。

用户选择一个目录后，必须启动其实际要求的解析流程：不能把快速模式的旧任务当成准确模式，不能跨账号返回旧任务，不能把旧文件版本的结果当成新文件版本。

## 本轮行为

1. 保留现有选择指纹，另在 `large_catalog_imports.selection_snapshot.import_identity` 中记录有效解析模式、账号、来源根目录和版本摘要。版本摘要包含实际导入路径、已登记 SHA-256、尺寸和纳秒修改时间；不是仅比较文件名，也不会重新读取几十GB正文。
2. `auto` 按已有 Worker 约定使用 `accurate`，现在扫描记录也保持一致，不再展示为 `fast`。
3. 相同请求号、相同选择和相同身份仍返回原任务；账号、模式、来源或选择变化返回409，明确要求刷新后使用新请求号。新请求号只有在上述信息一致且原任务仍活动时复用。
4. 旧快照没有新身份字段时，从原任务的解析参数和持久化文件清单恢复身份。相同的历史请求仍可正常重试，不以新格式为由一律拒绝。损坏或缺少校验依据的快照不被默认为可复用。
5. 复用判断读取桥接记录对应的原始解析任务，不再被更晚创建的摘要子任务状态误导。原任务丢失时，新请求不返回失效的任务号。
6. 来源元数据每500条读取一批，各批共享同一SQLite读快照，读取结束关闭连接。来源库不可用返回503，不再降级成无指纹任务；选择后文件被移除或尺寸/修改时间变化时返回409。
7. 当前来源库标记为敏感的文件同样被排除。排除后的路径一致进入 `scan.selected_paths`、选择表、任务目标、深读选择与检查点。原请求路径保留用于审计，`imported_paths` 表示实际导入范围，计数和字节数分别记录请求范围与实际范围。
8. 原有单事务写入及 `BEGIN IMMEDIATE` 内二次判重保留。不同模式的并发请求不能合并；同一请求号却要求不同模式的并发请求只有一个成功，其余返回409。

## 兼容与不变项

- 不改变初步摘要的“结论—支撑证据”格式，不改变邮件、翻译和文件保护开关。
- 不添加数据库迁移、额外模型、后台常驻任务或文件复制。
- 旧版代码可以忽略新增快照字段；代码回滚不需要还原业务数据库。
- 源文件在选中后还可能继续变化。本轮核对的是已登记来源版本；物理文件在解析前的快照与稳定性验证仍由现有普通解析器负责。这不构成任意操作系统文件操作的完整审计或阻断。
- 未登记SHA-256时，版本区分依赖尺寸和修改时间，不能据此证明正文未变；登记哈希本身是否最新也依赖来源索引更新。不得把本轮元数据一致性校验描述为对所有物理文件变化的密码学证明。
- 压缩包内部的逻辑成员仍遵循原有明确限制，本轮未宣称打通该情形。

## 验证与证据

- `tests/test_catalog_import_identity.py` 覆盖解析模式、账号隔离、版本变化、敏感排除、无效快照、历史兼容、任务丢失、子任务干扰、并发判重、多批次一致读与选择/清单一致性。
- `tests/test_catalog_import_api.py` 通过真实ASGI路由验证202创建/200复用、409模式或来源冲突、401未认证、503来源库故障及排除文件不进入Worker目标；保持既有非归属/不存在包统一400的兼容响应，两者响应内容相同且不创建任务。使用临时存储，不运行应用启动生命周期，不代表线上已激活补丁。
- 扩大回归曾暴露既有防护测试的时间漂移：参数在收集阶段取当前时间加600秒，执行超过300秒后不再属于非法未来时间。已将测试改用固定参考时钟，并补充允许边界与超界用例；生产时间校验仍为300秒，未放宽保护规则。原失败日志保留为 `clock-drift-tests.log/json`。
- 修复前第一批20个新增用例中19个失败、1个通过；修复后第一批相关回归112项及8个子测试通过。后续扩大回归和最终复测结果保存在本轮备份目录中的日志与JSON记录，不用本段代替最终结果。
- 最终扩大回归：**462 passed，8 subtests passed**，pytest耗时300.37秒；另行真实HTTP接口验收：**5 passed**，pytest耗时7.19秒。`final-tests.json` 与 `http-tests.json` 保存通过状态和对应源码SHA-256，安装脚本在合入前逐项核对；不把分开运行的测试套件描述成一次全仓测试。
- 扩大回归使用临时状态目录、明确的空环境文件、离线模型地址，避免回落到生产环境配置。
- 5000/50000文件基准只衡量合成清单的任务创建、同号重试和活动任务复用，不包含真实文件正文、解析、模型推理、GPU或端到端问答；不能据此声称几十GB真实资料已验收。
- 新的版本核验有必要的元数据读取与哈希开销，不能把正确性修复宣传为所有请求都更快。对照数据须与完整性检查一同保存。

1. 本轮备份：`.codex-backups/engineering-round2-identity-20260927/`，含基线源码、隔离副本、测试日志及文件哈希。备份不纳入Git。

3. 测试通过和提交代码不代表现有Python进程已经加载新版本。服务重载必须另行核实正在执行的任务、管理方式和可恢复性，不直接杀掉工作进程。
   本次核对发现既有重启脚本会整体停止Web、普通Worker和大包Worker，并在超时后强制收尾；现有看门狗也可能触发整体重启。本轮不执行这些脚本，不停止后台任务，不修改这些项目外脚本。代码安装后须另行安排受控激活和运行中接口验收。
4. 回滚采用本轮提交的精确反向补丁或逐文件备份，先确认没有后续改动；不回滚整库，不重置其他人的工作。
