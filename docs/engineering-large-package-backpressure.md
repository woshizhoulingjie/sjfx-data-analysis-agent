# 大数据包长任务：资源背压与无损恢复

## 目的与范围

100GB是输入规模，不是某个固定完成时限。本轮保证大包遇到资源不足时不继续
挤占临时空间、不把系统故障写成文件质量失败、不凭空生成成功的空预览。
解析预算、采样策略、目录算法、模型设置、证据、权限和翻译/保护功能均不降低。
本轮实现不是100GB端到端吞吐验收，也不是全系统统一容量预留器。

## 当前发现

- 启动时的包容量估算不能替代长任务中的持续检查。
- 状态盘、解析临时盘与Python系统临时盘实际上位于不同设备。
  2026-09-26只读快照中前两者约112GiB/3.23TiB可用，而`/tmp`仅约3.4GiB。
  这些是采集时的瞬时值，不是持久保证或可处理包大小。
- 原预览器会把部分OSError转成警告；子进程又把异常类型压成字符串，
  有机会把内存、磁盘配额或文件句柄不足误记成普通不完整预览。
- 原队列领取会增加attempts。基础设施恢复不应该耗尽文件内容的失败额度。

## 行为契约

1. 大包worker每个调度周期、盘点写入批次和解析领取批次执行准入检查。
   正常状态的实际磁盘探测最多每秒一次，各线程共享检查状态。
2. 分别检查索引、解析临时目录、Python临时目录、SQLite默认VFS临时目录。
   SQLite目录按官方Unix规则寻找，不把Python的`tempfile`结果直接视作SQLite目录。
   项目未使用`temp_store_directory`或自定义SQLite VFS。
3. 磁盘余量至少1GiB，并尊重既有解析空间预留配置；恢复需要额外256MiB余量。
   资源异常进入30秒退避。每次轮询不会延长同一次退避，空间恢复后自动继续。
4. 暂停领取新的工作；已经结束的其他预览仍尝试正常提交，不丢弃其有效内容。
   用户暂停/取消语义保持原样，不强制恢复用户暂停任务。
5. 仅当前租约持有者可把资源失败的队列项放回retry，并退回本次领取增加的1次attempt。
   不清除历史真实失败次数；重复退款和过期租约都被拒绝。
6. 资源异常不改文件原文、摘要、证据、SHA256、覆盖质量或选择范围。
   普通内容/格式/权限问题继续既有路径，不能统一伪装成资源等待。
7. ENOSPC、EDQUOT、ENOMEM、EMFILE/ENFILE、MemoryError以及既有SQLite资源分类
   通过预览子进程边界保留类型。进程启动失败会关闭已创建的两端管道。
8. 空间检测或目录发现失败也是可恢复等待。盘点期间句柄耗尽不能变成跳过目录。
9. 既有页面的任务说明显示等待原因，日志记录资源类别。数据库连说明都无法写入时
   不伪造成功，保留日志和原租约恢复机制。没有使用旧数据库覆盖新业务记录。

## 不声称已经解决的问题

- 这是准入下限，不是每个任务的剩余容量估计；不同进程不会共享空间预约。
- 检查与分配不是原子的：其他程序仍可能在两次检查之间消耗磁盘。
- 已进入模型或本地库的调用不能在任意指令点安全暂停。
- QA已有独立资源保护；普通解析、翻译、保护等进程没有因为本轮而被全局接管。
- 若SQLite本身无法进行任何写入，立即回队也可能失败，需要既有租约过期恢复。
- 原有每文件内存/时间预算不变；未声称解决所有解析库、OOM-kill或第三方协议错误。
- 目录、研究方向、普通解析与问答仍需整链路实证，不能用本轮预览基准替代。

## 验收方法

- `tests/test_large_package_resources.py`使用真实SQLite队列，覆盖低磁盘、恢复余量、
  退避到期、跨进程错误类型、句柄回收、过期租约、批量提交异常、盘点中断、
  其他完成任务的保存、恢复后同一文件完成以及普通内容错误不被掩盖。
- 相关大包、桥接、目录、QA和安全测试在禁止联网的独立状态目录执行。
- 已发现3项既有工作流断言在未修改源码备份中同样失败：暂停时完成结果如何记账、
  小包主题层、旧的theme_leaf_files层级期待。保留对照结果，不删除或改写测试凑绿。
  这些问题需单独核对当前产品契约，不能据此宣称全系统验收完成。
- 性能对照使用400份中英泰文本、4条车道、三组交错顺序运行，比较真实文本预览
  与队列提交段，并对样本、画像、分类、覆盖字段做完整结果指纹对比。
  不计模型/目录生成，不是完整子进程协议或真实100GB吞吐测试。

## 原始研究依据

- Welsh, Culler, Brewer, *SEDA: An Architecture for Well-Conditioned, Scalable
  Internet Services*, SOSP 2001，阶段队列、资源控制和背压讨论：
  https://www.sosp.org/2001/papers/welsh.pdf
  本项目采用停止接纳新工作和保留队列的思路，不采用丢弃事件或降低内容质量。
- SQLite官方结果码定义：https://www.sqlite.org/rescode.html
  基础设施错误需要区别于内容解析错误，扩展码按其主码分类。
- SQLite官方临时文件说明：https://www.sqlite.org/tempfiles.html
  临时文件可能位于数据库之外的卷；Unix临时目录选择顺序有独立规则。
