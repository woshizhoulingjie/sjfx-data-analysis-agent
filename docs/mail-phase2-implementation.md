# 邮件分析二期实施说明

本次版本：2026-10-06。在一期拆包、正文/附件、线程、人物、混合检索和证据定位基础上，新增共享的事项、原子通信行为、版本状态与语义审核台账。

## 使用入口

- 阅读邮件 → 分析单封意图：分别保留请求、提议、接受、拒绝、修改、撤回等表达及原文。
- 人物 → 全部往来分析：先逐批读可用文本，再核查会话、原子结论和事项对齐，最后生成人物主题概览。共享事项另有分页入口。
- 双方往来/通信图连线 → 分析双方意图：按事项、对象版本、参与方显示表达状态、条件、变化和资料缺口。
- 自然语言研究：按证据需求规划，混合检索增加原子台账召回，分配支持/反证/条件/更新的证据上下文，并按核验缺口有界补检。
- 通信图：重点概览、搜索全部人物、逐页展开联系对象；结构关系与事项证据层切换；时间窗、截止日期、双方泳道和原文回查。

## 状态与证据

事项标题不是身份依据。无编号的事项先保留为暂定，经过双侧原文对齐才归并。模型只给候选；系统复查来源、范围、参与方、对象和版本约束。

同一事项的 v1 拒绝与 v2 附条件接受分开保存。当前表达按 actor/object/version/time 派生；旧会话的最严重审核标签另行显示，不能覆盖其他版本状态。明确撤回与假设或否定撤回分开处理。

“收到”不能推出“同意”，“声称完成”不能推出现实已完成。条件满足情况未经独立证明时保留待核实。辅助语义裁判使用同一模型，不构成独立事实验证。全部文本遍历与全部行为抽取、概览覆盖分别披露。

## 范围、缓存与恢复

来源引用再次检查原文哈希、位置、作者归属、资料包和授权用户。图谱游标绑定范围、数据版本、节点、事项与时间。图谱发起分析时，服务器验证 manifest 并固定范围；不能仅依赖浏览器筛选。

完成缓存绑定源内容、引擎版本、人物归并与共享台账依赖。正文变化、事项映射变化或引擎变化会拒绝复用不适用结果。原始邮件和已有研究结果不覆盖。

单封、双方与人物分析恢复已保存游标；普通研究恢复原轮次及累计调用、token、工具、时间和补检消耗，并在原范围内重新检索核验。重新分析创建新轮次和新预算。模型失败和预算停止不能标为完整研究。

## 配置与回退

`MAIL_PHASE2_ENABLED=1` 为默认启用。关闭该开关并重启 Web/普通 Worker 可回到原研究路径；新附加表保留。源码回退使用本次备份，避免用数据库整体恢复抹掉部署后新增资料。

普通研究默认 token 预算 120000、上下文预算 12000、补检最多 2 轮、补检候选 40。对应环境变量：`MAIL_RESEARCH_MAX_TOKENS`、`MAIL_RESEARCH_CONTEXT_TOKENS`、`MAIL_RESEARCH_GAP_ROUNDS`、`MAIL_RESEARCH_GAP_CANDIDATES`。单封/双方/人物入口提供调用和 token 上限，并保留实际 provider usage；没有 usage 时明确采用估算。

数据库仅新增 v6 表与索引，保存代际、行为、事项、映射、断言链接、可重算状态及抽取缓存。历史邮件在新分析时逐批生成台账；未生成台账不解释为没有事项。

## 验证范围与后续评测

自动化验证覆盖范围隔离、截止时间、引用与作者、条件、版本、拒绝/撤回、同事项对齐、预算停止恢复、缓存失效、图谱分页、过期响应和浏览器联动。实模型烟测只用虚构谈判邮件，不能当作真实业务准确率。

研究方案中的人工双人标注、留出集准确率、复杂社区摘要、模型训练及预测属于后续评测/研究，需要实际标签和业务决策。本次没有宣称完成这些统计结论，也没有训练 GraphRAG、RAPTOR 或 TGN。原子台账召回采用字面索引入口，保留已有正文向量检索。

当前单 Web 实例使用进程内签名与数据观察缓存。重启后旧图谱游标需重载；扩成多 Web 实例时，应先部署共享签名与统一数据版本来源。
