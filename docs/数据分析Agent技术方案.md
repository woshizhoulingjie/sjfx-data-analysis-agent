# 数据分析 Agent 技术方案

---

## 1. 产品定位

帮助情报分析师/研究员在面对一批**完全未知的数据包**时，短时间内拿到全局概览，并按需下钻到感兴趣的部分做深入分析。

---

## 2. 核心约束（v0.2 强化）

| 约束 | 说明 |
|---|---|
| **物理断网** | 本Agent运行在独立设备上，与公网完全隔离 |
| 数据规模 | 几百 GB，单包输入，非持续流式 |
| 数据来源 | 客户自有 + 外部采集均可（通过物理介质导入） |
| 客户先验 | 客户对包内内容**无任何先验知识** |
| 模型依赖 | 本地大模型推理，不依赖云端 API |
| 与整编Agent关系 | **物理隔离**，数据流转通过物理介质（U盘/移动硬盘）手工中转 |

---

## 3. 不实现功能说明

| 功能 | 决策 | 原因 |
|---|---|---|
| 去重 | **暂不实现** | 几百 GB 规模下，全量 embedding 比对 O(n²) 不可接受 |
| 聚类 | **暂不实现** | 同上 |
| 向量存储 | **不需要** | 目录树浏览和深度摘要均无需向量检索 |
| 跨产品UI跳转 | **不实现** | 双盒子断网部署下，UI层无法互联 |

---

## 4. 三类交付物

数据分析 Agent 产出三类独立交付物，**形态与用途各不相同**：

| 交付物 | 形态 | 用途 |
|--------|------|------|
| **① 交互式目录树 + 摘要视图** | 盒内交互界面 | 客户在本机深度探索数据包，逐层下钻 |
| **② 情况概览报告** | Word报告（.docx） | 客户对陌生数据包的全局理解文档，可存档可分享 |
| **③ 导出的待整编数据包** | 文件包 | 衔接整编Agent的中间产物，客户通过U盘手工中转 |

---

## 5. 技术架构

```
几百GB数据包（物理介质导入）
         │
         ▼
┌─────────────────────────────────────────────┐
│  Level 1: 文件级解析（所有文件）              │
│  Docling 解析 → 文件元数据                  │
│  无 LLM 调用                                │
└────────────────────┬────────────────────────┘
                     │
                     ▼
┌─────────────────────────────────────────────┐
│  Level 2: 文件夹级概览                       │
│  简单摘要（异步生成）                        │
│  轻量 LLM 调用                              │
└────────────────────┬────────────────────────┘
                     │
                     ▼
┌─────────────────────────────────────────────┐
│  目录树 UI（文件系统结构）                    │
│  ├── 展开/折叠                              │
│  ├── 点击 → 查看摘要                         │
│  └── 导出按键 → 生成待整编数据包             │
└────────────────────┬────────────────────────┘
                     │
                     ▼
┌─────────────────────────────────────────────┐
│  情况概览报告生成（自动）                    │
│  Word报告自动生成到输出目录                  │
└─────────────────────────────────────────────┘
```

## 6. 分层处理流程

### 6.1 Level 1：文件级解析

| 项目 | 说明 |
|---|---|
| 处理范围 | 所有文件 |
| 处理方式 | Docling 解析 |
| LLM 调用 | 无 |
| 输出 | 文件元数据（路径、大小、类型、页数、结构） |

```json
{
  "file_path": "/data/folderA/report.pdf",
  "file_name": "report.pdf",
  "file_type": "pdf",
  "file_size": 2048576,
  "page_count": 15,
  "structure": {
    "has_title": true,
    "has_toc": true,
    "table_count": 3,
    "image_count": 5
  },
  "parsed_at": "2026-08-04T10:00:00Z"
}
```

### 6.2 Level 2：文件夹级概览

| 项目 | 说明 |
|---|---|
| 处理范围 | 每个文件夹 |
| 处理方式 | Docling 解析结果 + 简单摘要 LLM |
| LLM 调用 | 轻量（每文件夹一次） |
| 输出 | 文件夹摘要（文件列表、粗粒度描述） |

```json
{
  "folder_path": "/data/folderA",
  "file_count": 12,
  "total_size": 104857600,
  "file_types": ["pdf", "docx", "xlsx"],
  "summary": "该文件夹包含12份文档，主要涉及2026年第一季度安全事件报告...",
  "generated_at": "2026-08-04T10:05:00Z"
}
```

### 6.3 Level 3：深度摘要（按需）

| 项目 | 说明 |
|---|---|
| 触发时机 | 用户点击文件时 |
| 处理方式 | Docling 深度解析 + LLM 摘要 |
| LLM 调用 | 按需 |
| 输出 | 文件结构概览 + 核心内容摘要 |

```json
{
  "file_path": "/data/folderA/report.pdf",
  "structure_overview": {
    "title": "2026年第一季度安全报告",
    "sections": ["概述", "事件统计", "区域分析", "结论"],
    "page_count": 15,
    "tables": 3,
    "figures": 5
  },
  "core_summary": "本报告汇总了2026年第一季度全球安全事件共计3,204起...",
  "generated_at": "2026-08-04T10:10:00Z"
}
```

## 7. 情况概览报告（新增核心交付物）

### 7.1 报告定位

情况概览报告是数据分析 Agent 的**独立交付物**，描述的是"这个数据包大概在讲什么"，不是"对某个主题的深度判断"。

### 7.2 内容结构

| 章节 | 内容 |
|------|------|
| 数据包基本信息 | 总文件数、总大小、时间范围（如可推断）、来源构成 |
| 全局分类 | 目录树的顶层展开（通常2-3层）+ 每个顶层节点的摘要 |
| 关键发现 | 异常点（如：某类文档占比异常高） |
| 深入方向建议 | Agent主动给出"哪些节点值得优先下钻到整编Agent"的建议 |

### 7.3 深入方向建议规范

深入方向建议应标注为推论 + 给出依据：

```json
{
  "direction": "建议优先对folderA/author_reports进行整编",
  "type": "推论",
  "confidence": "中",
  "evidence": [
    {
      "reason": "该节点含50份文档",
      "fact": "folderA/author_reports 包含50份PDF"
    },
    {
      "reason": "主题集中度高",
      "fact": "均为同一作者关于网络安全的研究报告"
    }
  ],
  "confidence_note": "基于节点内容量与主题集中度判断"
}
```

### 7.4 生成时机

| 时机 | 说明 |
|------|------|
| **自动生成** | 客户导入数据包后，Agent完成解析 + 目录树构建后自动生成一份 |
| **手动重新生成** | 客户在交互界面上深入探索后，若对数据包的理解发生显著变化，可触发"重新生成概览报告" |

### 7.5 约束

- 本报告是 Agent 自动整理的全局快照
- 不受整编 Agent 的"事实/推论分离 + 强制可溯源"硬约束
- 报告生成在盒子的输出目录，客户通过物理介质（U盘/移动硬盘）带出

## 8. 目录树交互设计

### 8.1 支持的操作

| 操作 | 说明 |
|---|---|
| 展开/折叠 | 文件夹的展开折叠 |
| 点击 | 查看该文件夹/文件的摘要 |
| **导出按键** | 将选中节点的文件 + 节点摘要打包为待整编数据包 |

### 8.2 导出待整编数据包

| 导出范围 | 说明 |
|---------|------|
| 单个文件 | 导出该文件 + 其深度摘要 |
| 整个文件夹 | 导出文件夹内所有文件 + 文件夹摘要 |

### 8.3 数据包导出流程

```
客户点击"导出待整编数据包"
         │
         ▼
┌─────────────────────────────────────────────┐
│  Step 1: 收集选中节点的文件列表              │
└────────────────────┬────────────────────────┘
                     │
                     ▼
┌─────────────────────────────────────────────┐
│  Step 2: 获取节点摘要                        │
│  - 文件级：深度摘要                           │
│  - 文件夹级：文件夹级摘要                     │
└────────────────────┬────────────────────────┘
                     │
                     ▼
┌─────────────────────────────────────────────┐
│  Step 3: 打包为待整编数据包                   │
│  - 文件本体                                   │
│  - 节点摘要.json                             │
│  - 打包为zip/tar格式                         │
└────────────────────┬────────────────────────┘
                     │
                     ▼
┌─────────────────────────────────────────────┐
│  Step 4: 输出到盒子的导出目录                 │
│  客户通过U盘/移动硬盘手工拷贝到整编Agent       │
└─────────────────────────────────────────────┘
```

### 8.4 与整编 Agent 的衔接

```
数据分析 Agent 设备                    整编 Agent 设备
┌─────────────────┐                  ┌─────────────────┐
│                 │    U盘/移动硬盘    │                 │
│  导出待整编数据包 │ ───────────────→ │  导入到素材目录   │
│  (含文件+摘要)   │    客户手工操作    │                 │
└─────────────────┘                  └─────────────────┘
        ↓                                    ↓
   输出目录存储                          客户在整编Agent
   供物理介质带出                       发起新任务
```

**关键约束**：两台设备之间**无网络通信**，所有数据流转通过物理介质由客户手工完成。

## 9. 技术栈

| 层级 | 技术选型 |
|---|---|
| 文档解析 | Docling + RapidOCR |
| 本地 LLM | vLLM / Ollama |
| 目录树 UI | Web 前端（React/Vue）+ 后端 API |
| Word 生成 | python-docx |
| 状态管理 | SQLite |
| 文件系统遍历 | Python os/scandir |
| 数据打包 | Python zipfile/tarfile |

## 11. 约束条件

| 条件 | 说明 |
|---|---|
| **物理断网** | 最高优先级约束，所有能力依赖本机资源，不允许任何外部API调用 |
| **部署形态** | 独立算力盒子，与整编Agent设备物理隔离 |
| **数据中转** | 物理介质（U盘/移动硬盘），客户手工操作，两台设备间无网络通信 |
| 数据规模 | 几百 GB，单包输入 |
| 模型依赖 | 本地大模型推理，不依赖云端 API |
| 输入格式 | PDF、Word、Excel、PPT、图片（OCR），不支持视频 |
| 输出形态 | 交互式目录树 + 摘要视图 + 情况概览报告（Word） |
| 下钻整编 | 导出数据包，客户手工拷贝到整编Agent设备 |

## 12. 与整编 Agent 的关系

### 12.1 逻辑协同

```
客户视角典型工作流：

1. 客户面对陌生数据包，先在数据分析Agent上获取全局概览
   ↓
2. Agent自动生成《情况概览报告》，客户通过U盘带出存档
   ↓
3. 客户在交互界面上深入探索目录树，识别值得深入的方向
   ↓
4. 客户导出待整编数据包，通过U盘拷贝到整编Agent设备
   ↓
5. 客户在整编Agent上对该子集做深度整编，产出主题报告
```

### 12.2 数据安全边界

| 原则 | 说明 |
|------|------|
| 物理隔离 | 两台设备之间无任何网络通信 |
| 客户主导 | 数据流转由客户手工完成，Agent不感知另一台设备的存在 |
| 安全可控 | 流转过程由客户掌控，不引入网络通信风险 |
