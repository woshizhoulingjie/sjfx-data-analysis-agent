# 1GB / 5GB / 10GB 数据包性能验收

本基线用于验证“可恢复地分批处理约 10GB 数据包”。每次验收必须使用同一台服务器、同一模型和同一解析模式，并保留机器、软件版本及原始结果 JSON。

## 覆盖等级

| 等级 | 含义 | 最低要求 |
| --- | --- | --- |
| `inventory_complete` | 全量盘点 | 全部路径、格式、大小和哈希进入清单；失败和跳过可见 |
| `representative_overview` | 有界内容解析 | 全量文件进入批次处理，但部分文件正文受解析上限或格式能力限制 |
| `full_text_analysis` | 全文深度分析 | 无待处理、失败、抽样或不完整文件；压缩包成员也全部完成 |

## 固定测试矩阵

分别准备约 1GB、5GB、10GB 的真实混合数据包。每档至少包含 PDF、DOCX、XLSX、PPTX、CSV/JSON、图片、ZIP，并包含以下边界样本：精确重复副本、近似版本、损坏文件、GB18030 文本、扫描型 PDF、大表和含不支持成员的压缩包。

每档执行：

1. 首次完整盘点和全量分批解析。
2. 对同一主题执行两次证据检索，验证缓存复用。
3. 选中一个主题重新分析，验证未变化文件复用检查点。
4. 人工停止 Worker 后恢复任务。
5. 导出原始资料与分析成果交接包。

## 必须记录的指标

- 输入：总字节数、文件数、格式分布、压缩包成员数、规范文档数、重复副本数。
- 覆盖：已解析/失败/待处理/抽样/截断文件数及字节数，压缩成员成功/跳过/失败数。
- 性能：盘点耗时、解析耗时、Embedding耗时、主题建树耗时、概览报告耗时、端到端耗时。
- 资源：CPU 平均值和峰值、RSS 内存峰值、磁盘读写字节、数据库和缓存增长量。
- 质量：去重准确率、主题纯度、证据有效率、错误合并率、错误拆分率、人工目录满意度。
- 恢复：单文件失败是否影响其他文件、取消响应时间、重启后是否从检查点继续。

## 建议验收阈值

这些阈值是工程门槛，不是对不同国产芯片的最终性能承诺。正式芯片对比时应在同一数据集上重新给出 P50/P95。

| 指标 | 1GB | 5GB | 10GB |
| --- | ---: | ---: | ---: |
| 全量盘点成功率 | >=99.9% | >=99.9% | >=99.9% |
| 任务可恢复率 | 100% | 100% | 100% |
| 无证据正式结论数 | 0 | 0 | 0 |
| 内存峰值 | <=系统内存70% | <=系统内存70% | <=系统内存70% |
| 磁盘剩余空间 | >=20% | >=20% | >=20% |

端到端耗时受文件类型和 OCR 页数影响，不能只按GB给固定秒数。应分别报告“纯文本/Office”“普通PDF”“扫描PDF”三组 P50/P95，并在结果中写清 OCR 页数和模型 Token 用量。

## 执行命令

```bash
python scripts/benchmark_package.py /data/benchmark/1gb --label 1GB --mode fast
python scripts/benchmark_package.py /data/benchmark/5gb --label 5GB --mode fast
python scripts/benchmark_package.py /data/benchmark/10gb --label 10GB --mode accurate
```

结果默认写入 `outputs/benchmarks/`。验收时不得使用稀疏文件冒充真实解析负载；稀疏文件只可用于验证扫描和容量边界。
