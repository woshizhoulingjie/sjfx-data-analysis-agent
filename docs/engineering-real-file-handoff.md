# 真实文件交接与分页目录完整性

## 背景与验收范围

在 `796bc478452750365edac5c1987af1c7cdfc7980` 基线上，用真实文本和ZIP经过大包清点、导入交接、普通解析与初步摘要任务派发。不是只验证数据库里产生了任务号。

发现并修复以下问题：

1. 选择 `region/team/reports/one.txt` 时，只保存直接父目录，上级目录缺失，完整树出现孤儿文件。现在为实际导入文件建立去重的全部父目录闭包，仍不把未选择的兄弟文件带进来。
2. `reports.zip/one.txt` 可以是真实文件夹中的普通文件，不能只看扩展名就当成压缩包内部成员。新清点将物理来源持久化，导入时只相信来源数据库，不相信前端或调用者传入的标记。
3. 原分页投影把目录的子项数写为0，把根目录的全部后代数当成直接子项数；界面因此无法展开，或出现没有内容的下一页。现在从已有完整树线性生成各节点的直接子项数和同级顺序，分页树与完整树一致。

## 数据库与兼容性

- `large_package.db.files` 增加 `source_kind TEXT NOT NULL DEFAULT ''`。使用现有增量迁移机制，不删除旧列或表，不重建业务资料。
- 真实文件清点写 `physical_file`；明确的归档内部成员可标记为 `archive_member`，但本轮没有生成这类成员清单。未知或未提供的来源保留为空。
- 旧行不自动冒充已经验证的物理文件。旧的含归档式路径的数据仍采用保守限制；重新执行真实清点后才能获得明确来源标记。
- 桥接的元数据读取兼容尚未增加该列的旧库，读取时不进行迁移。来源库故障继续关闭导入，不降级成无核验任务。
- 来源标记只是清点来源说明，不是文件内容安全证明。普通解析仍执行源文件稳定性、白名单、文件句柄和符号链接检查。目录在交接后被替换成符号链接也不能因此绕过保护。
- 旧版代码不读取新列，代码回滚不需要删除它。不能为回退代码而覆盖整个业务库，避免丢失备份之后的新任务。

## 真实ZIP与逻辑成员的区别

选中真实 `package.zip` 整个文件，沿用既有普通解析器，验收已检查其正文证据被保存并派发初步摘要任务。

选中ZIP中的单独成员是另一个能力：大包当前清点物理文件，尚未建立成员级内容清点、目录和安全交接。本轮不取消该限制，也不把不存在的成员路径当作物理文件。既有 `pack.zip/member.txt` 模式与普通流程使用的 `pack.zip::member.txt` 逻辑表示都应明确区分。
