## 证据链定位

证据链适合作为数据分析智能体的结构化输出，主要服务于三处：节点摘要回查、研究方向依据、待整编数据包交接。它不会把“情况概览”扩张为报告整编智能体的正式专题报告，也不会替代后续整编阶段更严格的事实/推论审计。

统一证据字段包括：`evidence_id`、`source_path`、`page`、`section`、`label`、`text`、`bbox`、`score`、`parser`、`source_sha256`、`content_sha256`。

本地 RAG 对上述证据块建立 BM25 与 TF-IDF 字符向量混合排名。研究方向优先使用检索结果，不再只引用首段；要求/说明材料会标记为独立资料角色，尽量避免污染研究主题判断。

## 技术方案冲突处理

早期技术方案 v0.2 曾把去重和聚类列为“不做”，老师最新交付要求把二者列为数据分析 Agent 的 P0。当前实现以老师交付要求为验收基线，因此补上包内精确去重和高相似聚类；其余模块边界仍遵循技术方案。
