# 大数据包内容目录 v2

2026-09-10。仅作用于独立大包目录；源文件、普通导入和已保存的深度摘要不重写。

## 行为

文件全量盘点与有界内容预览 → CPU 语义分组 → 组级模型命名 → 可选上层导航 → 70% 等待用户选择深度摘要。

名称来自3～5份代表材料的内容。保留核心、差异以及覆盖全组的稳定抽样；不依赖文件名来推断主题。输入引用保留原文件及片段位置。每份证据除正文片段外，还带上预览阶段**已经算好**的 fields（字段）、keywords（关键词）与 headings（章节标题），模型先看结构化线索判断"这份材料讲什么"，正文片段只作佐证——此前这些字段一路算完却从未进入命名提示词。

输入同时给出该组的成员总数与抽样份数，避免把单份样本特有的细节当成全组共同主题。正文里的 HTML/XML 源码在进入证据前剥离（实测约 5% 的文件首段证据是 `<!DOCTYPE html>` 源码）；剥离后没有可读正文的，走既有的"无正文"路径，不虚报为已读懂。

确无共同主题、证据不足、只会说泛化词，都按**状态**处理而不是当作目录名：校验器把它们归一到 `内容主题不统一（待细分）`、`证据不足（待补充内容）`、`名称过于泛化（待细分）`三个规范名，并置 needs_review。规范状态名不参与同名归一与等义合并（那些流程只处理 needs_review=0 的标签）。含泛化词但确实具体的名称（例如“就业与消费政策汇编”）保留名称、只置复核标记。扫描失败、尚无正文、需OCR等单独展示，不虚报为已读懂。

目录使用稳定节点编号。模型名称存在组级表中，不为重命名而修改每个文件；同名组不合并。支持按名称搜索、节点分页、人工修改名称并锁定、从历史版本恢复。人工名称不会被自动改名覆盖。

已有大包不自动重做预览。进入“大包目录 → 智能目录 → 完善目录名称”可从保存的内容生成新名称。新包自动在70%之前完成首轮有预算的命名。深度摘要更新后仅为受影响的组排队；用户选择的路径保持不变。

## 首轮默认预算

- 最多100次生成请求，包含失败重试及上层归纳。
- 输入+输出最多200000 tokens；调用前原子预留，完成后按usage核销。
- 每次输入最多3500 tokens（含提示与聊天开销预留）；输出最多240 tokens。
  输入预算由 2500 提到 3500 的依据是本机服务实测的时间成本结构：**输入约
  0.7ms/token 且命中前缀缓存后接近 0，输出约 22ms/token**（3,861 token 预填充
  2.70s、同内容再来 0.66s；输出 768 token 16.75s）。多给的 1000 token 用来放
  每份材料的结构化档案，同时收紧输出（description 由 20–60 字改为 20–40 字），
  净时间成本约 +8%。批次输入上限同步由 6500 提到 10000，否则单组变大后每次
  调用只能装 1～2 组，反而放大往返开销。
- 命名窗口600秒，包括排队；单请求等待最多30秒。
- 每项最多1次自动重试，不叠加客户端自动重试。
- 上层导航是可选的一次短请求，最多4个分支，未被归入分支的底层主题仍显示。

任何总预算到限都停止派发，目录先可用。请求取消或内容版本变化后，旧响应不能覆盖新结果。服务端可能在客户端超时后短暂继续收尾；超时后后台请求隔离30秒，前台不受该隔离限制。

预算、请求幂等键、缓存、任务租约与历史保存在large_package.db。重启、重复点击及暂停恢复不自动清零预算。相同内容的已完成节点不会因“完善目录”重新消耗模型请求。

## 运行参数

SJFX_LP_CATALOG_MODEL_NAMING=1
SJFX_LP_CATALOG_REQUESTS=100
SJFX_LP_CATALOG_TOTAL_TOKENS=200000
SJFX_LP_CATALOG_SECONDS=600
SJFX_LP_CATALOG_INPUT_TOKENS=3500
SJFX_LP_CATALOG_OUTPUT_TOKENS=240
SJFX_LP_CATALOG_TIMEOUT=30
SJFX_LP_PREVIEW_CONCURRENCY=2
SJFX_SHARED_GENERATION_GATE=1

向量输入按本机tokenizer预算覆盖标题及不同正文位置；不可用时用保守长度回退。生成模型继续复用本机服务，未调整GPU服务并发或加载另一个模型。

共享生成入口让网页、普通Worker、大包Worker跨进程排队。普通现有请求保持FIFO；自动目录命名优先级较低。正在生成的请求不能瞬间被本地队列抢占，但目录请求有短输入、短输出和超时边界。

## 验证与局限

已进行目录、预算、取消、恢复、同名分组、内容版本、人工锁定、分页、父子范围与跨进程前台优先测试；与改造前的全项目测试做过对照。

真实20份PDF的完整盘点、预览、命名、上层归纳约60秒。此样本不代表100GB的整体耗时。十万条合成文件记录（逻辑总大小约100GB）的目录分页测试只验证清单规模，不等同真实读取100GB数据。

层级推断和自然语言名称仍需要抽样核对。内容混杂时标记待复核，源文不足时保留内容标题。实体匹配及引用校验不是校准概率，也不证明所有成员已被全文分析。

**已知未覆盖**：名称与证据之间的**语义**支撑仍未校验——本地复现显示校验器接受“海洋珊瑚白化机理”配数据库事务证据（needs_review=false）。这一步需要组画像（c-TF-IDF + 文档频次）与留出成员复核，属于下一阶段（L2/L3）。乱码正文（PDF 内嵌字体缺映射）不再进入语义归纳，但文件仍保留在清单与画像中，等待 OCR 或补充识别。

## 回退

关闭SJFX_LP_CATALOG_MODEL_NAMING后重启大包Worker即可停止新增自动命名；已有标签仍可读取。上层导航或单个名称可按目录版本回退。代码更新前保留原文件与SQLite在线备份；数据库改造只增表、列和触发器，旧代码可继续读取既有文件与摘要表。
