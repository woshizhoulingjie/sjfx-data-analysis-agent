# 人物活动报告与深度分析

人物页的“通读整个资料包并生成完整报告”先扫描所选资料包内全部可用邮件正文和附件文字，包括人物未出现在收发角色中的邮件。浏览邮件时的时间、关键词和收发筛选不缩小报告范围。

第一步报告按邮件时间概括人物的行动陈述、所受要求、对外要求、回应、收到的信息、关联材料记录及后续变化。正文使用事件编号和证据编号，全部逐字引文集中在文件末尾的“原文支撑”附录。附录记录邮件日期、主题、发件人、正文或附件位置、附件文件名、页码或单元格、字符位置，并提供来源查看入口。导出为 UTF-8 BOM Markdown，下载内容与完整预览一致。

第一步不推断心理。收到或抄送信息不代表接受，要求和未来承诺不代表已执行，报告发运不代表对方已收到或完成验收。邮件中的本人陈述与其他人的反馈分别保留。

完整报告完成后，用户填写关注的事情、对象或东西，以及态度、想法或意图问题，发起第二步深度分析，无需先勾选事件。第二步复用已验证完整事实报告的全部规范事件、时间线和精确原文引文，模型仅针对对象综合本人态度、可能的想法与意图、条件、后续与反证；意图假说应说明不确定性和其他解释。请求必须绑定同一用户、资料包、人物和原文指纹的已完成第一步报告。

## API

- `POST /api/mail/packages/<id>/person/analyses`：`analysis_mode=full_report`、`address` 或人工人物 `entity_id`；可传模型调用和 token 总预算。第一步目标固定。
- 同一路径第二步：`analysis_mode=deep_analysis`、`source_report_turn_id`、`target`、`question` 及同一人物。
- `GET /api/mail/person-analyses/<id>` 与 `/report`：任务状态、真实批次进度和报告。
- `GET /api/mail/person-analyses/<id>/report/download`：已完成报告文件，沿用当前用户鉴权。
- `POST /api/mail/person-analyses/<id>/resume`：从失败、停止或预算耗尽检查点继续；原文或人物邮箱集合变化时拒绝混用。

新任务使用分析版本 3。未显式指定 `analysis_mode` 的旧客户端及已有版本 2 任务保留原执行方式。没有数据库迁移。

## 完整范围与进度

第一步的 `report.complete` 表示当前资料包的全部可用文本已逐批处理并生成文件。第二步继承该覆盖，`report.complete` 另要求对象综合与文件整理完成；继承满覆盖本身不能证明深度分析已经完成。`report.source_complete` 单独说明正文及附件文本是否存在缺口；缺失或部分附件逐项计数并在报告中说明。扫描完成不等于证明现实事件全部发生，也不意味着资料包含有所有历史通信。

第一步每批必须确认全部新增原文片段并通过引用及角色校验；事实报告再用一次有明确上限的原文忠实与完整性校核，校核通过后才保存本批事件与累计覆盖；截断或无效批次不推进游标。跨批衔接文字仅用于理解，不重复累计阅读字数。第一步进度区显示已保存字数、正在处理的批次字数、时间范围、模型等待或运行状态。报告生成前可以停止并保留已提交批次。

第二步直接进入 `deep_synthesis`，不重新执行逐批阅读和事实校核。`progress` 与 `report.coverage` 用 `coverage_source=completed_activity_report` 和 `coverage_inherited_from=<父报告任务编号>` 标明覆盖来源，父报告已完成的字数及扫描标志保存在各自的 `source_coverage`。本轮原文扫描字数和批次数均为零；`progress.source_scan_complete=true` 说明父报告完成扫描。深度综合沿父事实报告的引用链校验综合结论，保留父报告的完整事实时间线与精确引文；界面显示继承覆盖和本轮模型等待、综合运行及实际计时，只有父报告绑定及继承覆盖完整、任务完成、`progress.complete` 和 `report.complete` 同时成立后才提供深度文件下载。

预算累计实际或估计消耗；结构修正不会在一次预留外偷偷追加模型调用。深度汇总沿引用链保留来源日期、陈述性质和不确定性，背景资料不能升级为人物明确表达的态度。
