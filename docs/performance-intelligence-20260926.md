# 情报概览与保质量提速（2026-09-26）

## 用户可见变化
- 普通数据包和大数据包共用情报阅读面板，沿用系统 `--p-*` 主题变量、字体、圆角和原有导航。
- 推荐方向突出核心研究问题、推荐理由、研究动作、预期产出、代表资料和支撑原文；仅展示简报实际提供的内容。
- `方法 → 产物` 分别显示为“研究动作”和“预期产出”；无产物的旧简报不自动补造。
- 深度解析与快速解析分开展示；未知值显示未知，不用零值制造完成状态。保留原图表、原文、问答、报告下载和研究详情。
- 同内容轮询不重建面板；更新保留展开状态和焦点；证据内容变化也会刷新；切包移除旧资料。
- 两条报告提示词要求具体对象、比较维度、原文核验点及“动作 → 产物”，禁止编造机构、时间、数字和未完成结论。已有报告缓存不自动重跑。

## 提速实现
1. 普通包并行解析优先提交较大文件，仍按原索引交付结果；并发上限、取消语义和逐文件错误保留。串行/自定义解析器不改变顺序。文件大小是耗时启发式，不保证所有格式均受益。
2. 文档向量沿用原内容哈希、原画像、原模型缓存域。相同键只请求一次并回填所有别名；批量默认由6改24，上限64，客户端自身限额仍生效。
3. 精确token计数用线程安全LRU缓存，键包含实际tokenizer对象和完整输入；最多256项/200万输入字符。无证据截断、无计数近似。
4. 大包命名先准备一个批次；存在缓存命中、混合路线、超限或无效候选导致未满批时，继续有界准备窗口。候选总上限24不变，避免一次准备3批但仅使用1批。
5. 已有模型请求期间预热后续证据缓存，全worker最多1个后台任务、默认4组、最大8组。不增加模型请求、不领取任务、不发布名称。作用域退出等待自己发起的预热完成。预热可写入原证据缓存。

## 不改变的质量边界
保留来源哈希、所有者隔离、修订号/租约检查、原证据预算、留出成员校验、JSON与名称校验、人工锁定、暂停取消、失败重试及提交前状态检查。不替换分组算法，不把文件名当证据，不降低模型输出预算。

## 配置与回退
| 环境变量 | 默认 | 回退/说明 |
|---|---:|---|
| `PARSE_LARGEST_FIRST` | `1` | `0`恢复并行提交原顺序 |
| `SEMANTIC_EMBEDDING_BATCH_SIZE` | `24` | `6`恢复原调用批量 |
| `SJFX_LP_CATALOG_PREPARE_LIMIT` | 当前命名批量 | `24`恢复候选全窗口准备；不小于命名批量 |
| `SJFX_LP_EVIDENCE_PREFETCH` | `1` | `0`关闭证据预热 |
| `SJFX_LP_EVIDENCE_PREFETCH_GROUPS` | `4` | 限定1..8组 |

调整环境变量后需重启相关进程。配置文件、线上GPU服务参数和系统全局主题未随此补丁修改。完整回退应使用部署前逐文件备份，并先核对当前文件未被别人修改。

## 证据与验证口径
- 新测试覆盖调度顺序/结果顺序/取消/单文件异常、向量别名与跨模型隔离、LRU边界、预热生命周期、满批准备/混合路线补位/异常候选补位。
- 前端覆盖转义、未知统计、深浅覆盖、来源入口、切包清理、手机无横向溢出、真实CSS层叠、焦点与展开保持、同数量证据内容刷新。
- tokenizer微基准使用真实Qwen tokenizer及合成重复文本；不是模型生成或整包耗时。
- 目录基准使用真实批处理代码与SQLite、12个合成组和同一模拟模型。它测准备工作，不测GPU推理。原代码每轮总准备24次，优化12次；每版都完成12组、3次模型调用。
- 真实用户资料包全流程耗时、GPU吞吐和推荐方向人工质量验收仍需独立对照，不能由微基准推导。
- 全量回归曾超时；最终结果以交付报告记录的明确测试范围为准，不称全项目全绿。

## 调研来源与采用方式
- vLLM Automatic Prefix Caching：https://docs.vllm.ai/en/latest/features/automatic_prefix_caching/ 。生产已启用，不重复开启作为成果。
- vLLM：https://github.com/vllm-project/vllm 。借鉴有界批处理和复用；本补丁不改变GPU并发。
- PagedAttention：https://arxiv.org/abs/2309.06180 。用于判断显存和吞吐约束，未盲目扩大接近满载GPU的参数。
- RAPTOR：https://arxiv.org/abs/2401.18059 。参考层级摘要与原文可追溯的分离，没有替换现有目录算法。
- BERTopic：https://github.com/MaartenGr/BERTopic 与 https://arxiv.org/abs/2203.05794 。参考嵌入、主题表示及批处理分工，没有引入额外依赖或重写分组规则。
