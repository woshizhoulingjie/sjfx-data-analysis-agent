# 第四轮：异步目录与情报概览一致性

## 范围和基线

基于 `b0914dac1220147df83d8aa233d026c48ed806e2` 做增量修复，不改页面接口、不改普通摘要“结论—支撑证据”结构、不执行数据库迁移。先前未提交改动已由初始基线提交保存，本轮没有覆盖它们。

备份与隔离验收目录：`.codex-backups/engineering-round4-real-model-flow/`。其中 `baseline.tar` 与 `manifest.json` 是改动前源码归档及校验；`predeploy/` 为安装前逐文件备份；`evidence/` 保存修复前后回归记录；`guarded-trial/` 保存独立数据库和合成样本。

## 真实缺陷

六份有确定事实的合成文档经过本机实际生成模型及嵌入模型后，叶组命名和拆分晚于第一版概览。原工作进程遇到 `overview-v1.json` 就永久跳过目录概览更新，空闲补发也跳过已有版本。结果目录已经完成，报告仍引用早期分类骨架，正式视图的目录版本为空。

另有两个一致性缺口：只用行数和最大时间戳判断缓存会漏掉同数量、同时间戳的重命名；模型生成期间目录变化时，旧证据报告可能被绑定到更新后的目录版本。

## 修复

- 新增有界目录内容签名，覆盖组成员修订、标签版本/名称/说明/摘要哈希、主题结构与待办命名状态；不加载向量或大段证据正文。
- 用内容签名使报告缓存失效，旧版报告缺少签名时自动更新一次。
- 已有概览也参与后台补发；输入未变时不再生成、不重复发布、不调用模型。
- queued/running/retry/deferred 都计入未完成命名，部分报告保留显式说明；命名排空后可更新。
- 发布前在写事务内重新核对输入签名。目录版本登记与发布视图指针在同一事务提交，过期生成结果不覆盖有效报告。
- 发布校验失败时不冒用旧目录版本；其他既有目录调用方仍保留原有回退契约。
- 第一版成功发布后保留为历史快照；后续目录刷新不把深度概览降级为第一版。
- 报告 schema 递增为 `large-package-report/2.6`，为兼容性新增字段。

## 验收证据

新增九项离线回归覆盖刷新、空闲补发、深度版本保留、时间戳不变的重命名、过期发布拒绝、旧报告升级、运行中命名、无效目录版本及无 v1 的深度报告不空转。前六项在原始基线上全部失败，修复后全部通过；扩展回归的精确源码哈希和结果见 `evidence/final-regression-tests.json`。

真实模型验收使用 `qwen3.6:27b` 与 `multilingual-e5-small`，独立 state 目录，不替换业务组件。六份文档均有实际正文，快速解析和目录任务均完成，命名待办为零；正式目录与报告共同引用 `cat-5b5aeaa51aa682beb35f`。报告骨架从 `category` 更新到 `topic`，且签名对应当前目录。验收恢复后还要求签名稳定至少十秒，不能依赖工作进程重启后丢失的内存标记。

初次验收脚本缺少多进程入口保护，曾发生子进程重复执行初始化；该次结果无效，错误日志完整保留。随后使用独立的 guarded-trial 状态重新执行。存在报告、任务已排队或单次退出码为零，都不作为全流程通过证据。

## 明确未完成

这不是几十 GB 全链路或内容质量的最终验收。当前小样本主题仍存在聚合偏宽的问题：独立 P-99 维护记录被放在含极光项目的上位主题下；研究方向代表证据覆盖还不充分。普通导入、真实问答、选定深度摘要、邮件意图、数据库容量和授权客户端保护需要继续分轮验证。

本轮不重启生产服务、不推送 Git，不把源码提交等同于线上进程已经加载新版本。服务器路径不能凭空推导任意客户端本地路径；本地防护必须依赖明确授权的端点映射及操作系统执行机制。

## 回滚

仅回滚本轮源码提交，或在核对后按 `predeploy/` 恢复本轮三个既有模块并移除本轮新增测试/说明。不要把历史整库覆盖到运行中的业务数据库，否则会丢失本轮期间新增的业务活动。任何受控上线、进程替换和真实容量压测另行记录。
