# 百GB数据包工程化：目标与验收

更新日期：2026-09-26。持续目标已启动；此文档不是100GB验收通过证明。

## 不变的交付边界

- 保留现有导入、分析、目录、研究、问答、邮件、翻译、保护和权限功能。
- 不覆盖其他人正在修改的翻译、文件保护代码，不夹带尚未上线的邮件版本。
- 所有性能提升均须保留文件、证据、敏感信息限制、引用和失败可见性。
- 大包轻量预览不等于完整正文解析。分别报告文件枚举、预览、向量、目录命名、研究方向、选中深读和问答耗时。
- 真实数据保留在用户服务器，公开资料研究不上传业务文档。

## 递进研究流程

1. 枚举大包，展示已发现文件、总字节、阶段进度、失败及可恢复状态。
2. 生成有来源证据的智能目录和具体研究问题；标出只读过摘要与已完成原文解析的范围。
3. 用户从目录或研究方向选择关联文件，使用现有大包→普通包桥接建立分析任务。
4. 保留选择快照、原包标识、源文件指纹、排除列表和幂等请求；不重复复制大文件。
5. 普通分析完成后开展深入研究与资料问答，答案引用须能回到原文；缺证据时明确说明。
6. 重试、暂停恢复、删除引用保护、并发用户和跨用户隔离需要单独验收。

## 已发现的工程问题与本阶段范围

- 问答索引旧实现同时全量加载源记录和现有索引记录；向量及长摘要使内存随包规模增长。候选实现用索引所在卷的磁盘暂存、128条稳定批次、版本连接与单事务发布。
- 大包导入选择允许5万路径，但去重使用列表查找。改为集合判断并保留首次出现顺序、原路径校验。
- 正常泰文曾被乱码门槛拒绝。仅补充已分配Thai字符区间；不降低乱码比例阈值、不接受未分配字符及私用乱码。
- 泰文全文检索分词仍是后续项：不能只修改分词函数，因为已有contentless FTS删除需要与旧索引token一致；必须设计索引版本迁移及中英泰检索评测。
- 现有桥接已实现，不另造重复导入通道；归档内部成员的导入限制需明确告知并单独解决。

## 实测环境与限制

- 16核CPU，约31GiB内存，单张RTX3090 24GiB，模型服务显存已接近占满。不得盲目提高GPU并发或并行加载新模型。
- 原始项目/资料位于NAS；状态数据库位于本机/home盘。SQLite WAL数据库不能迁到共享网络文件系统用于多机并发。
- 审计时/home可用约112GiB，/tmp总容量约5.5GiB。100GB解包必须单独评估扩张率、临时文件、索引、WAL及保留空间，不能默认全部放/tmp。
- 当前登记39个大包，最大约3.62GB；这不构成100GB覆盖。

## 分阶段验收

| 阶段 | 验证内容 | 必须保存的证据 |
|---|---|---|
| 安全基线 | 源码、配置、数据库在线快照与校验；并行变更检查 | 备份manifest、SHA256、quick_check、精准回滚工具 |
| 局部优化 | 原版/新版相同输入、完整输出等价、不隐藏失败 | 索引和引用指纹、测试结果、耗时、峰值RSS及Python内存 |
| 真实小包 | 中英泰、Office/PDF/文本/邮件、受限与损坏样本 | 目录和研究方向人工评审，固定问题集、原文引用核对 |
| 扩容压测 | 逐步提升文件数、单文件大小与总字节 | 首次可用时间、各阶段p50/p95、吞吐、内存、磁盘/WAL、失败和恢复时间 |
| 真实100GB | 用户授权的约100GB真实资料，实际格式和语言分布 | 清单总数/总字节、完整阶段计时、遗漏清单、结果覆盖、人工抽查 |
| 可交付 | 大包→普通包→问答全流程、权限、回滚演练 | 可重复执行步骤、健康检查、任务恢复证据、上线版本 |

“可接受时间”还需在实际100GB样本和硬件条件下定为明确SLA；在此之前只报告实测，不能把元数据基准外推为整包耗时。首次可用目录与完整目录分别计时，冷缓存、热缓存及并发负载分开报告。

## 方法依据与适用范围

- SQLite WAL官方文档：https://www.sqlite.org/wal.html 。采用一致读快照及及时释放源读事务，避免长时间阻碍checkpoint。
- SQLite FTS5官方文档：https://www.sqlite.org/fts5.html 。保留contentless索引原有删除与token语义，验证删除后无残留命中。
- Python sqlite3官方文档：https://docs.python.org/3.12/library/sqlite3.html 。显式关闭源连接；连接上下文管理本身不等于close。
- Unicode Thai字符表：https://www.unicode.org/charts/PDF/U0E00.pdf 。用于泰文已分配字符质量判断，不是分词算法。
- Unicode分段规范：https://www.unicode.org/reports/tr29/ 与PyThaiNLP：https://github.com/PyThaiNLP/pythainlp 。用于后续泰文分词选型；需词典/语言机制及索引迁移验证。
- M3-Embedding：https://arxiv.org/abs/2402.03216 。多语、稀疏/稠密检索的候选方向；未替换当前模型，论文指标不等于本系统指标。
- Self-RAG：https://arxiv.org/abs/2310.11511 。支持按需检索与证据自检的研究方向；未声称实现其训练与反思token机制。
- PagedAttention：https://arxiv.org/abs/2309.06180 。作为服务批处理与KV缓存诊断依据；不直接套用论文吞吐提升倍数。
