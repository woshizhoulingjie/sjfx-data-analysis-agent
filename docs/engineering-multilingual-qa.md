# 大包资料问答：中英泰关键词检索

## 行为与范围

- 原有中文二元词、英文数字分词和 contentless `search` 表完全保留。没有泰文的查询继续使用原有检索与排序；不承诺中文问题能仅靠此改动跨语言检索泰文。跨语言语义检索仍由现有向量服务提供。
- 新增可重建的 `search_thai`，不改变 chunks 原文、页码、定位、摘要、向量模型或生成质量设置。PyThaiNLP 5.3.8 的 `newmm-safe` 使用固定内置词典，不加载模型、不下载语料、不调用外部服务。
- NFC 保留声调与组合元音；分词结果编码为 ASCII 词项，避免 SQLite 默认 tokenizer 再次切断泰文字母。没有删除泰文否定词或停用词。
- 连续书写的泰文存在上下文切分差异。例如“งบประมาณการชำระเงิน”的切分未必含单独的“งบประมาณ”。低权重的原字串短语索引补充精确子串召回；不删除声调、不把不同空格两侧拼成一个短语，不是模糊拼写替换。
- 泰文词法结果与现有词法、向量、主题材料以现有 RRF 融合；仅含泰文的问题启用新的选段词项。一次请求内缓存最多512条分词结果，不跨请求缓存业务正文。

## 安全与版本

- 所有词法检索仍在 LIMIT 前执行目录/文件授权；继续重新确认源库成员与敏感标记，并校验实际文件大小、时间、路径边界。
- 泰文查询使用绑定的JSON授权集合一次检索，避免每500个授权路径重复扫描同一词项；`query_only`始终开启。不带JSON扩展的SQLite保留分批兼容查询，各批取150后全局合并，不少取本应入选的材料。
- 算法、词典指纹、index_epoch、generation 一起形成版本戳。旧二进制回滚后写入会使戳失效，检索显示准备/更新警告而不信任陈旧泰文词项。
- 初次升级采用128块的 keyset 批次；SQL预筛泰文块，不把全库正文加载到Python。原子事务内建立派生表，增删正文同步维护新旧索引。
- 分词失败、依赖丢失、资源耗尽均不允许提交“少了若干段”的原文。失败回滚旧原文、旧FTS和版本；资源异常保持原类型以触发资源退避。检索降级须显示可能遗漏泰文材料的警告。
- 空索引和无泰文索引的时延不能作为实际泰文检索性能。首次升级有额外扫描、CPU和磁盘代价，必须单列测量。

## 发布与回滚

先校验新源码和所有QA索引在线备份，完成隔离测试及副本基准。保持翻译、保护、普通worker和大包worker代码不变。索引准备只暂停QA单写入者；主网页可继续使用旧检索。主程序用原参数/环境温和重载，等待Uvicorn正在处理的请求结束，不强杀。存在活动业务任务时延后发布。

精确回滚只恢复本次修改且未被后来改修的源码；未使用的 `search_thai` 派生表和词典依赖可以保留供旧代码忽略。**不得用发布前的整库覆盖期间新增的业务记录。** 后续再升级时generation校验触发安全重建。
